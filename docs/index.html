Getting started

  1. Download and start the Windows executable.
  2. Enter an NTP/NTS hostname or IP address.
  3. Choose request count and delay.
  4. For NTS, enable NTS (TCP 4460) and normally keep TLS verification enabled.
  5. Start the test and watch the running log and statistics.

Public NTS test

Use time.cloudflare.com, enable NTS, and leave certificate verification enabled. A successful run reports NTS-KE SUCCESS followed by NTS AUTHENTICATED.

NTP peer monitoring and fault injection

The v2.1.0 development build adds an integrated NTP Peer Test Responder. Point an NTP client or peer at the responder and monitor its incoming requests while returning controlled normal or adverse protocol conditions.

Original modes are valid, kod (RATE), bad-originate, short, and duplicate. Advanced cases add DENY/RSTR KoD, wrong mode/version, zero T2/T3, LI=3, stratum 16, drop, one-second delay, ±100 ms timestamp offsets, 100 ms server processing delay, and replay.

Understanding the results

NTS-KE SUCCESS

TLS key establishment succeeded and negotiated the NTS protocol and AEAD.

UID matched

The authenticated response corresponds to the request being validated.

S2C tag verified

The response authenticator verified with the negotiated server-to-client key.

Cookie pool

Replacement cookies allow continued authenticated UDP exchanges without keeping TLS open.

Long-duration testing

500 requests at a 5000 ms delay exercise a server for roughly 42 minutes plus processing time. A completed 500/500 run with zero Failures, NTS Failures and KoD Packets is useful evidence of protocol stability during the test interval.

Timing caveat

Client T1/T4 are Windows application/userspace observations, not Ethernet NIC hardware timestamps. OS scheduling, path asymmetry and timestamp placement can affect offset and delay.

Troubleshooting

Certificate name error

Use a hostname or IP covered by the certificate. Raw-IP operation requires a matching IP Subject Alternative Name.

NTS-KE timeout

Check TCP 4460 reachability, firewall policy and the NTS-KE service.

Authentication failure

Inspect UID/originate matching, negotiated keys, AEAD processing and the running log.

KoD response

A stratum-zero response can indicate an NTP control or rate-limit condition.
